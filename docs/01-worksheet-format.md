# 01. 교안 형식 (웹 우선, 인쇄 가능)

교안은 **화면에서 위에서 아래로 읽는 한 장의 웹 페이지**다. 같은 파일을 인쇄하면 활동마다 새 쪽에서 시작하는 학습지가 된다. 파일은 주차마다 `lesson.html` 하나다.

저장소 주인 피드백(2026-11-04)
- 레이아웃이 더 심플했으면 좋겠다.
- 컬러로 바꿔 달라(눈에 잘 안 들어온다).
- A4에 꽉꽉 채우는 학습지보다, 나중에 웹에서 교안으로 쓸 수 있는 형태까지 고려한다.
- (앞선 피드백) 한 번에 많은 정보를 담지 않으며, 일렬로 쭉, 쓰는 칸은 크게, 흐름이 매주 같아야 한다.

저장소 주인 피드백(2026-11-05, 2차)
- 할 일 목록을 없애고, 진행하면서 그 자리에서 바로 따라 할 수 있게 한다.
- 목표가 뚜렷하게 보여야 한다.
- 힌트 카드는 지금처럼 나란히 놓을 필요가 없다. 한 줄 너비를 다 써서 읽기 편하게 한다.
- 색: 미션·워밍업·단계(·바꾸기·새로 만들기)는 파랑, 도전 프로젝트는 주황, 힌트 카드는 회색

> 1학기에 이미 만든 `worksheet.html`(A4 고정 쪽 형식)은 예전 형식이다. 틀은 [templates/legacy/a4-worksheet-template.html](templates/legacy/a4-worksheet-template.html)에 보관했다. 새로 만들거나 고칠 때는 이 문서의 교안 형식을 쓴다.

## 원칙

1. **심플하게.** 활동 하나 = 흰 카드(블록) 하나. 굵은 테두리와 겹친 상자를 쓰지 않고, 여백과 색 막대로 구분한다.
2. **컬러로, 그러나 화려하지 않게.** 색은 파랑(기본)·주황(도전)·회색(힌트) 3가지만 쓰고, 색만으로 구분하지 않는다. 같은 활동에는 늘 같은 색과 이모지를 붙인다(색을 못 보는 아이, 흑백 인쇄 대비).
3. **목표가 먼저, 행동은 제자리에.** 할 일 목록은 두지 않는다. 블록 제목 바로 아래에 **📌 목표 한 줄**을 두고, 행동이 필요한 자리마다 번호 붙은 짧은 지시(① ② ③)를 둔다. 번호 지시에는 이모지를 붙이지 않는다 (3차 피드백) 아이는 위에서 아래로 번호를 따라가기만 하면 된다 (2차 피드백)
4. **한 블록에 한 활동, 위에서 아래로 한 줄.** 좌우로 나란히 놓지 않는다. 예외로 힌트 카드는 한 줄에 두 개씩 놓는다(코드가 든 ●●● 카드는 한 줄 전체, 휴대폰은 하나씩) (4차 피드백). 화면 폭이 넓어도 본문 폭은 820px로 둔다. 휴대폰에서도 그대로 읽힌다.
5. **매주 같은 흐름.** 블록 순서, 블록 안 순서, 색과 이름표가 매주 같다.
6. **쓰는 칸은 크게.** 인쇄해서 손으로 쓸 수 있는 크기로 둔다(아래 "칸 크기").

## 틀

- [templates/lesson-template.html](templates/lesson-template.html)을 복사해서 시작한다.
- `<style>`의 공통 스타일은 그대로 둔다. 꼭 필요한 것만 "주차별 추가" 표시 아래에 덧붙인다. 검사 도구가 공통 스타일이 템플릿과 같은지 확인한다.
- 외부 리소스는 Google Fonts만 쓴다. 그림 파일과 스크립트는 쓰지 않는다(웹 기능은 [decisions.md](decisions.md) P12).

## 활동 블록과 색 (고정 흐름)

색은 3가지만 쓴다(저장소 주인 선택, 2차 피드백): **파랑 = 미션부터 마무리까지 · 주황 = 도전 프로젝트 · 회색 = 힌트 카드**

| 순서 | 블록 (`section.block.○○`) | 색 묶음 | 이름표 |
| --- | --- | --- | --- |
| 1 | `mission` 오늘의 미션: 이야기, 오늘의 목표, 완성하면 이렇게 돼요 | 파랑 | 🎯 |
| 2 | `warmup` 워밍업: 고장 난 코드 고치기 | 파랑 | 🔧 |
| 3~ | `step` 단계 1, 2, 3 … (기능 하나 = 단계 하나 = 블록 하나) | 파랑 | 🪜 |
| 다음 | `change` 내 것으로 바꾸기 (오늘의 완성 기준) + 친구에게 보여 주기 | 파랑 | ⭐ |
| 다음 | `new` 새로 만들기(선택) + 오늘의 마무리 | 파랑 | 💡 ✅ |
| 다음 | `challenge` 도전 프로젝트 (일찍 끝낸 사람) | 주황 | 🚀 |
| 마지막 | `hints` 힌트 카드 | 회색 | 🃏 |

- 블록 안의 도구 카드는 회색 바탕(🧰)이다. 새 색을 더하지 않는다.
- 블록 안 작은 제목(`h3`, 예: ✅ 오늘의 마무리, 📌 오늘의 목표)과 이름표는 블록 색을 따른다. 검정 제목을 섞지 않는다 (5차 피드백)
- 이모지는 블록 제목, 미션의 📌 오늘의 목표, 📌 목표 줄, 🧰 도구 카드, ➕ 더 해 보기, 👀 친구에게 보여 주기에만 쓴다. ① ② ③ 번호 지시에는 쓰지 않는다 (3차 피드백)
- 힌트 카드 뱃지는 그 활동 블록의 색을 따른다: 단계·새로 만들기는 파랑, 도전은 주황. 카드 바탕은 회색 그대로다 (3차 피드백)
- 검사 도구가 블록 순서와, 블록마다 목표 한 줄이 있는지 확인한다.

### 단계 블록 안의 고정 순서

1. 제목: `단계 N` 이름표 + 만들 기능 (예: "제목 보여 주기")
2. 📌 목표 한 줄: 이 단계가 끝나면 무엇이 되는지 (예: "목표: 친구 이름을 물어보고 상자에 담는다")
3. 🧰 도구 카드: 그 단계에 처음 나오는 개념만. 없으면 생략. 카드 이름표에는 "도구 카드"라는 말 없이 **🧰 + 도구 이름**만 쓴다(예: "🧰 보여 주기: print()") (4차 피드백)
4. **① 기능 추가하기**: 이 단계에서 **새로 쓰는 줄만**. 지시 한 줄("`mini_starter.py`의 `# 단계 N` 아래에 입력")과 코드. 2단계부터는 첫 줄에 회색 주석으로 "# … 단계 N 코드 아래에 이어서"
5. **② 실행하고 확인**: 적을 양을 정한 지시(예: "마지막 줄 적기") + 쓰는 칸(여러 번 실행하면 "넣은 값 → 나온 말" 표) + 성공 체크
6. (마지막 단계) **③ 따라가기**

## 머리

- 주차 칩: `N학기 · N주차 · 부제`
  - 부제: 개념 주차는 그 주 개념을 "~하기"로(예: 묻고 답하기, 갈림길 만들기), 프로젝트 주차는 주차 성격(중간 프로젝트, 설계와 보충, 기말 프로젝트)
- 제목: 미니 프로젝트 이름
- 이름, 날짜 쓰는 줄

## 프로젝트 주차

| 주차 | 블록 |
| --- | --- |
| 중간 (5주) | mission / warmup / 주제별 퀘스트(step 자리) / 기획서 / 발표와 평가 / hints |
| 설계와 보충 (9주) | mission / warmup / step 1 주제·화면 흐름 / step 2 변수·리스트 표·순서도 / change "⭐ 설계도 점검"(★3) / new "💡 보충 문제"(설계를 마친 사람·추천받은 사람) / hints. 도전 없음 |
| 기말 (10~11주) | mission / 10주 warmup / step 1 명령 카드·시작 파일, step 2 최소 기준 만들기 / 11주 warmup / step 3 친구 테스트, step 4 발표 준비 / change "⭐ 기말 완성 기준"(★3 + 주제별 기준 체크 목록) / new "💡 추가 기능" / hints. 도전 없음 |

- 프로젝트 주차는 새 블록 종류를 만들지 않는다. 기존 블록의 제목과 내용만 바꾼다(2026-11-13).
- 여러 주에 걸친 교안(10~11주)은 주마다 워밍업을 둔다. 둘째 워밍업은 그 주가 시작하는 단계 바로 앞에 둔다. 단계 이름 끝에 `(10주)`, `(11주)`를 붙인다(2026-11-13). 검사 도구는 머리 칩이 `N~M주차`이고, 단계 이름 끝의 `(N주)`가 바로 앞 단계와 달라지는 단계 바로 앞일 때만 추가 워밍업을 허용한다(PR 리뷰).
- 기말 주제는 택1이고, 커리큘럼의 확장 주제(청소년 창업 시뮬레이션)는 도전 블록으로 나누지 않고 🚀 어려움으로 표시한다(2026-11-13).

| 이름표 | `.label` | "① 기능 추가하기" 같은 작은 제목(번호 + 이름, 이모지 없음) |

## 화면과 인쇄

- **화면:** 본문 폭 820px, 글자 17px, 휴대폰(560px 이하)에서는 여백과 글자를 줄인다. 긴 코드 줄은 가로로 스크롤된다.
- **인쇄:** `@page { size: A4; margin: 12mm; }`
  - 미션을 뺀 활동 블록은 새 쪽에서 시작한다.
  - 도구 카드, 코드, 쓰는 칸, 표, 힌트 카드는 쪽 사이에서 끊기지 않는다.
  - 긴 코드 줄은 줄바꿈된다.
  - 인쇄 설정: Ctrl+P → A4, "배경 그래픽" 켜기, 머리글·바닥글 끄기
- 점검 방법은 [04-review-checklist.md](04-review-checklist.md)에 있다.
- 이름표(`.label`)와 바로 다음 부품(코드, 쓰는 칸, 표)은 `.keep`으로 묶어 같은 쪽에 둔다. 이름표만 쪽 끝에 홀로 남지 않게 한다(생성 도구가 자동으로 묶는다) (2차 피드백)
- 인쇄 분량: 블록마다 새 쪽 구성은 그대로 둔다. 종이를 줄이려면 **양면 인쇄**를 쓴다(교사 가이드에 안내) (2차 피드백)
