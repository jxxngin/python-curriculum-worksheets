# 01. A4 워크시트 형식

워크시트는 **프린트해서 아이들이 손으로 쓰고 그리고 체크하며 활동하는 A4 학습지**다. 읽기만 하는 종이가 아니다. 파일은 주차마다 `worksheet.html` 하나다. 브라우저에서 열고 Ctrl+P로 인쇄한다.

## 틀

- [templates/worksheet-template.html](templates/worksheet-template.html)을 복사해서 시작한다.
- `<style>`의 공통 스타일은 **그대로 둔다**. 꼭 필요한 부품이 생기면 "주차별 추가" 표시 아래에만 덧붙인다.
  - 여러 주차에 쓸 만한 부품이면 템플릿의 공통 스타일로 올리고 [decisions.md](decisions.md)에 적는다.
- `.page > * { flex-shrink: 0; }`는 지우지 않는다. 카드가 몰래 줄어들어 내용이 잘리는 것을 막는다.
- 외부 리소스는 Google Fonts(Noto Sans KR, Nanum Gothic Coding)만 쓴다. 그림 파일과 스크립트는 쓰지 않는다.

## 쪽 규칙

- `<section class="page">` 하나가 A4 한 장(210×297mm)이다. 한 주차는 **3~8쪽**이다.
- 쪽마다 맨 아래에 `.foot`을 둔다: 왼쪽 `파이썬 N학기 · N주차`, 오른쪽 `쪽 / 전체쪽`.
- 내용이 넘치면 줄이거나 쪽을 나눈다. 쪽을 나누면 제목에 "(이어서)"를 붙이고 쪽 번호를 다시 매긴다.
- 쪽 아래가 절반 이상 비면 그 쪽 활동에 맞는 쓰기 칸을 늘리거나 내용을 옮긴다. 힌트 카드 쪽은 예외다.

## 1쪽 머리글

- 배지: `N학기` / `N주차` / 부제
  - 부제: 개념 주차는 그 주 개념을 "~하기"로 쓴다(예: 묻고 답하기, 갈림길 만들기, 숫자로 계산하기, 무작위로 뽑기, 조건 여러 개 다루기, 같은 일 반복하기, 여러 값 담기).
  - 프로젝트 주차는 주차 성격을 쓴다(중간 프로젝트, 설계와 보충, 기말 프로젝트).
- 제목: 미니 프로젝트 이름
- 부제목 줄: 오늘 쓰는 도구(개념·함수)를 `·`로 나열. 작게, 한 줄만
- 오른쪽: 이름, 날짜 쓰는 칸

## 개념 주차 쪽 구성 (프로젝트 중심)

수업 흐름의 원칙은 [02-content-rules.md](02-content-rules.md) "수업 흐름"에 있다. **개념 카드만 모아 둔 쪽은 만들지 않는다.**

| 쪽 | 섹션 | 손으로 하는 활동 |
| --- | --- | --- |
| 1 | 미션 브리핑(이야기, 완성하면 이렇게 돼요, 오늘의 미션) + ① 워밍업 | 오류에 동그라미, 줄 번호/오류 이름/고친 방법 표 |
| 2 | ② 따라 만들기: 단계 A·B(·C). 단계마다 목표 → 도구 카드 → 빈칸 코드 → 실행 기록 | 빈칸 채우기, 실행 전 예상과 실행 결과 적기, 따라가기 |
| 3 | ③ 내 것으로 바꾸기(완성 기준) + ④ 새로 만들기 + 친구에게 보여 주기 | 설계 표, 체크리스트, 계획 칸, 친구 한마디 |
| 4 | ⑤ 도전 프로젝트(선택) + ⑥ 오늘의 마무리 | 설계·그리기 칸, 체크리스트, 자랑하기, 스스로 평가 |
| 5 | 💡 힌트 카드 (오려 쓰기) | 선생님이 잘라서 나눠 준다 |

- 단계가 많으면 따라 만들기를 두 쪽으로 나눠도 된다.
- 섹션 제목에는 번호 원(`.num`)을 붙인다. 예상 시간(`.time`) 표시는 기준이 정해지면 따른다([decisions.md](decisions.md) P4).

## 프로젝트 주차 쪽 구성

| 주차 | 필수 쪽 |
| --- | --- |
| 중간 (5주) | 워밍업 / 주제별 미니 퀘스트 카드 / 확장 퀘스트 카드 / 기획서(주제, 화면 흐름, 변수 표, 쓸 개념 체크) / 발표 준비와 평가표 / 힌트 카드 |
| 설계와 보충 (9주) | 워밍업 / 기말 설계도 ①(주제와 최소 완성 기준, 화면 흐름) / 설계도 ②(변수·리스트 표, 개념 체크, 순서도) / 보충 미니 문제 / 힌트 카드 |
| 기말 (10~11주) | 워밍업 / 명령 카드 + 최소 완성 기준 체크리스트 / 2주 일정표, 친구 테스트 기록 / 주제별 설계 칸 / 발표 준비와 평가표, 학기 돌아보기 / 힌트 카드 |

## 부품

모든 부품의 예시는 템플릿에 있다.

| 부품 | 클래스 | 쓰는 곳 |
| --- | --- | --- |
| 코드 (줄 번호) | `pre.code` > `span.l` | 워밍업, 따라 하기, 개념 카드 |
| 코드 (줄 번호 없음) | `pre.code.nonum` | 파일 일부만 보여 줄 때 |
| 촘촘한 코드 | `pre.code.tight` | 긴 코드가 칸에 안 들어갈 때 |
| 줄 번호 맞추기 | `style="counter-reset: ln N"` | 앞부분을 생략하고 N+1번 줄부터 보여 줄 때 |
| 코드 빈칸 | `span.blank.w3[data-n="1"]` | 손으로 채우는 칸. 너비는 `w2`~`w5` |
| 실행 화면 칸 | `.screen` | 실행 전 예상, 실행 기록, 완성 화면 보여 주기 |
| 쓰기 줄 | `.lines` > `span` | 서술, 코드 손으로 쓰기 |
| 그리기 칸 | `.draw` | 화면 디자인, 순서도, 화면 흐름 |
| 이름표 달린 답 칸 | `.answer` > `.tag` | 계획, 아이디어 |
| 설계 표 | `table.fill` (`td.w`가 쓰는 칸, `.tall`은 높은 칸) | 변수 표, 규칙표, 기록표 |
| 체크리스트 | `ul.check` | 완성 기준, 마무리 |
| 미션 브리핑 | `.mission` (`.story`, `.screen`) | 1쪽: 이야기와 완성 화면 |
| 도구 카드 | `.tool` > `.th` | 따라 만들기 단계 안에서 새 개념 소개 |
| 퀘스트 카드 | `.quest` > `.qhead` + `.qbody` | 따라 만들기 단계, 바꾸기, 새로 만들기, 도전 |
| 개념 카드 | `.concept` | (예전 형식. 새 워크시트에서는 쓰지 않는다) |
| 힌트 카드 | `.hints` > `.hint` | 3칸씩, 쪽 사이는 `.cut`(가위선) |
| 화면 흐름 | `.flow` | 화면 ① → ② → ③ 그리기 |
| 2단 목록 | `.cols2` | 긴 체크 목록 |

## 디자인

- 흑백으로 인쇄해도 읽혀야 한다. 색에 의미를 담지 않는다(검정 잉크 + 회색 배경만).
- 이모지는 장식으로만 쓴다. 흑백으로 인쇄돼도 내용 이해에 지장이 없어야 한다.
- 손으로 쓰는 칸은 5~6학년 글씨 크기를 기준으로 높이를 잡는다(쓰기 줄 8mm, 표 칸 8~11mm).

## 인쇄

- 인쇄 설정: Ctrl+P → 용지 A4, 여백 기본값 또는 없음, "배경 그래픽" 켜기, 머리글·바닥글 끄기
- `@page { size: A4; margin: 0; }`과 `.page`의 297mm 높이로 한 섹션이 정확히 한 장이 된다.
- 점검 방법은 [04-review-checklist.md](04-review-checklist.md)에 있다.
