# 01. A4 워크시트 형식

워크시트는 **프린트해서 아이들이 손으로 쓰고 그리고 체크하며 활동하는 A4 학습지**다. 파일은 주차마다 `worksheet.html` 하나다. 브라우저에서 열고 Ctrl+P로 인쇄한다.

## 5~6학년을 위한 4가지 원칙

저장소 주인 피드백(2026-11-04): 지금 워크시트는 아이들이 무엇을 해야 하는지 이해하기 어렵다. 한 번에 너무 많은 정보를 담는다. 흐름이 눈에 익어야 한다. 쓰는 칸이 너무 작다. 일렬로 쭉 이어지는 것이 보기 편하다.

1. **할 일이 먼저 보인다.** 활동마다 맨 위에 "📋 할 일" 상자를 두고, 해야 할 행동을 번호 순서로 1~3개 적는다(예: 1. 코드를 따라 써요 2. 실행해요 3. 화면을 보고 적어요).
2. **한 쪽에는 한 가지 활동만 둔다.** 쪽마다 큰 덩어리는 3개 이하로 한다. 팁 줄, 작은 글씨 설명, 곁가지 정보는 넣지 않는다.
3. **일렬로 쭉, 매주 같은 흐름**
   - 모든 활동은 **위에서 아래로 한 줄(1열)**로 배치한다. 좌우로 나란히 놓는 배치(`.row`, `.grid2`)는 이름/날짜 칸처럼 아주 작은 것에만 쓴다.
   - 쪽 순서, 단계 안의 순서, 아이콘과 이름표를 **매주 똑같이** 쓴다(아래 "고정 흐름"). 아이들이 몇 주 지나면 보지 않고도 순서를 안다.
4. **쓰는 칸은 크게** 만든다(아래 "칸 크기").

## 틀

- [templates/worksheet-template.html](templates/worksheet-template.html)을 복사해서 시작한다.
- `<style>`의 공통 스타일은 **그대로 둔다**. 꼭 필요한 부품이 생기면 "주차별 추가" 표시 아래에만 덧붙인다.
- `.page > * { flex-shrink: 0; }`는 지우지 않는다(카드가 몰래 줄어들어 잘리는 것을 막는다).
- 외부 리소스는 Google Fonts(Noto Sans KR, Nanum Gothic Coding)만 쓴다. 그림 파일과 스크립트는 쓰지 않는다.

## 쪽 규칙

- `<section class="page">` 하나가 A4 한 장이다. 한 주차는 **3~10쪽**이다([decisions.md](decisions.md) P9).
- 쪽마다 맨 아래에 `.foot`을 둔다: 왼쪽 `파이썬 N학기 · N주차`, 오른쪽 `쪽 / 전체쪽`.
- 내용이 넘치면 줄이거나 쪽을 나눈다. 칸을 작게 줄여서 맞추지 않는다.
- 쪽 아래가 절반 이상 비면 쓰기 칸을 키운다. 힌트 카드 쪽은 예외다.

## 고정 흐름 (개념 주차)

| 쪽 | 활동 | 이름표 |
| --- | --- | --- |
| 1 | 미션: 이야기, 완성하면 이렇게 돼요, 오늘의 미션 | 🎯 |
| 2 | 워밍업: 고장 난 코드 고치기 | 🔧 |
| 3~5 | 단계 1, 2, 3 … (기능 하나 = 단계 하나 = 한 쪽) | 🪜 |
| 다음 | 내 것으로 바꾸기 (오늘의 완성 기준) + 친구에게 보여 주기 | ⭐ |
| 다음 | 새로 만들기(선택) + 오늘의 마무리 | 💡 ✅ |
| 다음 | 도전 프로젝트 (일찍 끝낸 사람) | 🚀 |
| 마지막 | 힌트 카드 (오려 쓰기) | 🃏 |

- 단계가 짧으면 두 단계를 한 쪽에 위아래로 둘 수 있다. 좌우로 나란히 두지 않는다.
- 섹션 제목에는 예상 시간을 쓰지 않는다(P4 결정 전).

### 단계 한 쪽의 고정 순서

모든 단계는 이 순서를 바꾸지 않는다.

1. **단계 머리** (`.stephead`): `단계 N` + 이 단계에서 만들 기능 (예: "제목 보여 주기")
2. **📋 할 일** (`.todo`): 번호 붙은 행동 1~3개
3. **🧰 도구 카드** (`.tool`): 그 단계에 처음 나오는 개념만. 없으면 생략
4. **⌨️ 따라 쓸 코드** (`pre.code`): 이 단계에서 **새로 쓰는 줄만**. 앞 단계 코드는 맨 위 회색 주석 한 줄로만 표시한다(`# … 단계 1에서 쓴 코드 아래에 이어서 써요`)
5. **▶️ 실행하고 확인** (`.screen.big` + 성공 체크 `ul.check`): 실행 화면을 적는 큰 칸, "□ 화면에 ○○가 나왔어요" 체크

## 1쪽 머리글

- 배지: `N학기` / `N주차` / 부제
  - 부제: 개념 주차는 그 주 개념을 "~하기"로 쓴다(예: 묻고 답하기, 갈림길 만들기, 숫자로 계산하기, 무작위로 뽑기). 프로젝트 주차는 주차 성격(중간 프로젝트, 설계와 보충, 기말 프로젝트).
- 제목: 미니 프로젝트 이름
- 오른쪽: 이름, 날짜 쓰는 칸

## 프로젝트 주차 쪽 구성

| 주차 | 필수 쪽 |
| --- | --- |
| 중간 (5주) | 워밍업 / 주제별 미니 퀘스트 카드 / 도전 퀘스트 카드 / 기획서(주제, 화면 흐름, 변수 표, 쓸 개념 체크) / 발표 준비와 평가표 / 힌트 카드 |
| 설계와 보충 (9주) | 워밍업 / 기말 설계도 ①(주제와 최소 완성 기준, 화면 흐름) / 설계도 ②(변수·리스트 표, 개념 체크, 순서도) / 보충 미니 문제 / 힌트 카드 |
| 기말 (10~11주) | 워밍업 / 명령 카드 + 최소 완성 기준 체크리스트 / 2주 일정표, 친구 테스트 기록 / 주제별 설계 칸 / 발표 준비와 평가표, 학기 돌아보기 / 힌트 카드 |

프로젝트 주차도 4가지 원칙(할 일 먼저, 한 쪽 한 활동, 1열, 큰 칸)을 따른다.

## 칸 크기

| 칸 | 최소 크기 |
| --- | --- |
| 실행 화면 적기 (`.screen.big`) | 높이 40mm |
| 쓰기 줄 (`.lines.big`) | 줄 간격 10mm, 3줄 이상 |
| 표의 쓰는 칸 (`table.fill.tall` `td.w`) | 높이 11mm |
| 코드 빈칸 (`.blank`) | 너비 24mm 이상(`w3`) |
| 그리기 칸 (`.draw`) | 높이 60mm |

## 부품

모든 부품의 예시는 템플릿에 있다.

| 부품 | 클래스 | 쓰는 곳 |
| --- | --- | --- |
| 미션 | `.mission` (`.story`, `.screen`) | 1쪽: 이야기와 완성 화면 |
| 단계 머리 | `.stephead` > `.n` | 단계 쪽 맨 위 |
| 할 일 | `.todo` > `ol` | 모든 활동 맨 위 |
| 도구 카드 | `.tool` > `.th` | 단계 안에서 새 개념 소개 (개념 카드 모양) |
| 코드 (줄 번호) | `pre.code` > `span.l` | 워밍업, 따라 쓸 코드 |
| 코드 (줄 번호 없음) | `pre.code.nonum` | 도구 카드 예시, 코드 일부 |
| 줄 번호 맞추기 | `style="counter-reset: ln N"` | N+1번 줄부터 보여 줄 때 |
| 코드 빈칸 | `span.blank.w3[data-n="1"]` | 바꾸기 등에서 손으로 채우는 칸 |
| 큰 실행 화면 칸 | `.screen.big` | 실행하고 확인 |
| 실행 화면 칸 | `.screen` | 완성 화면 보여 주기 |
| 큰 쓰기 줄 | `.lines.big` > `span` | 서술, 계획 |
| 그리기 칸 | `.draw` | 화면 디자인, 순서도 |
| 설계 표 | `table.fill.tall` | 변수 표, 규칙표, 기록표 |
| 체크리스트 | `ul.check` | 성공 체크, 완성 기준, 마무리 |
| 퀘스트 카드 | `.quest` > `.qhead` + `.qbody` | 바꾸기, 새로 만들기, 도전 |
| 힌트 카드 | `.hints` > `.hint` | 3칸씩, 쪽 사이는 `.cut`(가위선) |
| 화면 흐름 | `.flow` | 프로젝트 주차 설계도 |

## 디자인

- 본문 글자는 10.5pt 이상, 할 일은 11pt 이상으로 쓴다.
- 흑백으로 인쇄해도 읽혀야 한다. 색에 의미를 담지 않는다.
- 이모지는 고정 이름표(🎯 🔧 🪜 📋 🧰 ⌨️ ▶️ ⭐ 💡 ✅ 🚀 🃏)로만 쓰고, 같은 뜻에는 늘 같은 이모지를 쓴다.
