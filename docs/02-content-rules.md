# 02. 내용 규칙

## 대상과 수업

- 블록 코딩 경험이 있는 초등 고학년~중고등, 6명 미만 소그룹, 주 1회 110분, 편집기는 Thonny
- 초등은 미니 프로젝트 2단계 "바꾸기"가 그날의 완성 기준이다.
- 중고등은 미니 1단계 따라 하기까지 하고 확장 프로젝트가 완성 기준이다. 초등은 미니를 마친 뒤 확장을 고른다.
- 커리큘럼에 정해진 시간은 **주 1회 110분뿐**이다. 섹션별 시간은 기준 문서가 정한 기본값을 쓴다([decisions.md](decisions.md) 결정 대기 P4).

## 개념 범위

- **그 주차까지 배운 개념만** 쓴다(누적). 개념 목록은 [curriculum.md](curriculum.md)의 주차별 표를 따른다.
- 확장 프로젝트에서는 커리큘럼이 그 주에 명시한 함수를 써도 된다(예: 1학기 4주 math.pi, pow(), round(), max()).
- 커리큘럼 "참고"의 제외 목록(리스트 컴프리헨션, lambda 등)은 쓰지 않는다.
- 커리큘럼 "주차별 보완 메모"는 반드시 반영한다.
- 프로젝트 주차의 개념 체크 칸에는 아직 안 배운 개념을 넣지 않는다. 필요하면 "while·리스트는 아직이에요"처럼 적는다.

## 말투와 표기

- 학생용(워크시트, README): 친근한 존댓말(~해요). 한 문장은 짧게.
- 교사용(정답지, 교사 가이드): 간결한 평서문(~다).
- 변수 이름은 영어로 쓴다. 출력 문구와 주석은 한국어로 쓴다.
- 기존 게임·캐릭터·브랜드 IP를 쓰지 않는다.
- 교과 연계 사실(과학 수치, 역사 인물 등)은 정확해야 한다. 정답지에 근거를 적는다.

## 코드 규칙 (워크시트에 실리는 모든 코드)

- 들여쓰기는 항상 **4칸**이다.
- 긴 줄은 괄호 안에서만 나누거나, 변수를 하나 더 만들어 두 줄로 쓴다. **보이는 그대로 따라 쳐도 실행돼야 한다.**
- 워크시트에 실린 코드는 해당 `.py` 파일과 **글자 하나까지 같아야 한다**(질문 문구 포함).
  - 줄이 칸보다 길면 워크시트에서 줄이지 말고, 파이썬 파일 쪽 문구를 줄여 양쪽을 맞춘다.
  - 줄여 쓸 때는 `input(...)`처럼 생략을 드러내고 정답지에 적는다.
- 코드 조각만 보여 줄 때는 **빈칸 앞뒤 2~3줄을 함께** 보여 준다. 무엇을 비교하는지 종이만 보고 알 수 있어야 한다. 생략한 부분은 `# … ` 주석으로 표시한다.
- 빈칸 번호(①②③…)는 starter 파일의 `# 빈칸 N` 주석과 같다.

## 워밍업

- 매주 오류 3개짜리 코드를 고친다. 커리큘럼 운영 방식: 오류 메시지 읽고 고치기 + Thonny 디버거
- 주차마다 오류 종류를 섞는다. SyntaxError, NameError, TypeError, IndexError, AttributeError, IndentationError, 메시지 없는 오류(결과만 틀림), 무한 반복 중에서 고른다.
- 워크시트의 줄 번호는 `warmup.py`와 **같아야 한다**(Thonny 오류 메시지의 line 번호와 맞게).
  - 앞부분 주석을 생략하면 `counter-reset: ln N`으로 맞추고 "1~N번 줄은 설명 주석이라 생략했어요"라고 적는다.
- 하단 팁 줄에 그 주 오류 이름과 뜻을 짧게 적는다.

## 디버거 미션

- 그 주 개념을 **관찰하는** 활동이다(변수 값, 실행되는 줄 번호, True/False, 반복마다 바뀌는 값).
- 입력값을 정해 줘서 답이 하나로 정해지게 한다.
- 오류를 고치기 전 값을 묻는다면, 어떤 오류를 먼저 고쳐야 실행되는지 적는다(SyntaxError가 있으면 아예 실행되지 않는다).

## 개념 카드

- 개념 하나 = 카드 하나. 짧은 설명 + 3~6줄 코드 + "예상 실행 화면" 칸
- input()이 있으면 입력값을 카드에 적는다(👉 "응"이라고 입력했다면?).
- 무작위 결과는 "나올 수 있는 값을 모두" 쓰게 한다.
- 카드 아래에 직접 해 보기(손으로 코드 쓰기) 1개, 생각해 보기(서술) 1개를 둔다.

## 퀘스트 카드

- **1단계 따라 하기 (모두):** 빈칸 3~5개, 빈칸마다 짧은 힌트 줄
- **2단계 바꾸기 (오늘의 완성 기준):** 먼저 설계 표를 채우고 코드로 옮긴다. 체크리스트 4~5개 ([decisions.md](decisions.md) 결정 대기 P1)
- **3단계 새로 만들기 (선택):** 아이디어 2~3개 + 계획 칸
- **확장 프로젝트:** 빈칸 템플릿 없이 바꾸기부터 시작한다. 시작 파일은 그대로 실행돼야 한다.

## 힌트 카드

- 커리큘럼 운영 방식: 퀘스트 카드와 **3단계 힌트**
- 힌트 1 방향(●○○) → 힌트 2 쓸 함수(●●○) → 힌트 3 거의 코드(●●●)
- 미니 새로 만들기, 확장 새로 만들기, 따라 하기 빈칸 막힐 때를 3칸씩 둔다.
- 힌트 코드의 변수 이름은 학생이 쓰는 **starter 파일의 변수 이름과 같아야 한다**. 새 변수가 필요하면 힌트 1·2에서 먼저 소개한다(예: "infected를 sick과 total_sick으로 나눠요").
- 힌트 3 코드도 코드 규칙(4칸, 따라 쳐도 실행)을 지킨다.

## 예상 표 · 시뮬레이션

- 답이 하나로 정해지도록 **시작 조건과 계산 규칙을 모두** 적는다(예: "처음 감염자 1명, 아픈 사람마다 매일 2명씩").
- 그 조건으로 시작 파일을 실행하면 같은 답이 나와야 한다.
