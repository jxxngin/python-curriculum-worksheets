# 03. 파일 구성과 정답지

## 폴더

`worksheets/semesterN/weekNN/`. 여러 주에 걸친 프로젝트는 `week10-11/`처럼 쓴다.

## 개념 주차 파일

| 파일 | 내용 |
| --- | --- |
| `lesson_spec.py` | 주차 설계 파일. `python tools/lesson_gen.py`로 lesson.html·README·answer_key·mini 파일을 만든다 ([05-production-workflow.md](05-production-workflow.md)) |
| `lesson.html` | 교안. 화면에서 보는 교안이자 인쇄하면 학습지 ([01-worksheet-format.md](01-worksheet-format.md)). 예전 형식 주차는 `worksheet.html` |
| `README.md` | 교안 요약. GitHub에서 바로 읽히는 용도(P11). 교안과 같은 흐름·내용 |
| `warmup.py` | 오류 3개가 든 코드. 맨 위 주석에 "고쳐 보세요" |
| `mini_starter.py` | 아이가 이어 쓸 시작 파일. 코드 없이 단계 표시 주석만 있다(`# 단계 1: 제목 보여 주기` …). 아이는 단계마다 그 아래에 새 줄을 쓴다 ([decisions.md](decisions.md) P8) |
| `mini_solution.py` | 완성본. `# 단계 N: …` 주석으로 단계를 나눈다. 교안 단계 블록의 "🧩 기능 추가하기" 코드는 이 파일의 해당 단계 줄과 글자 하나까지 같다. 맨 아래에 바꾸기 예시 |
| `extension_starter.py` | 도전 프로젝트(커리큘럼의 확장 프로젝트) 시작 코드. 빈칸 없이 그대로 실행된다. 커리큘럼 보완 메모에서 제공하라는 코드는 여기 넣는다 |
| `extension_solution.py` | 도전 프로젝트 예시 답안 |
| `answer_key.md` | 교사용 워크시트 정답지 (아래 형식) |
| `teacher_guide.md` | 교사용: 110분 시간 배분(기본값 ±5분, [02-content-rules.md](02-content-rules.md)), 핵심 설명 포인트, 자주 나오는 오류와 대처, 진도 차이 대응 |

도전 프로젝트가 택1이면 `extension_<주제>_starter.py`처럼 주제를 붙인다.

## 프로젝트 주차 파일

| 주차 | 파일 |
| --- | --- |
| 중간 | 주제별 `midterm_<주제>_starter.py` / `_solution.py` |
| 설계와 보충 | `review_starter.py` / `review_solution.py` (보충 문제 전부) |
| 기말 | 주제별 `final_<주제>_starter.py` / `_solution.py` |

## 파이썬 파일 규칙

- solution과 도전 starter는 끝까지 실행돼야 한다. `mini_solution.py`는 단계 N까지만 남겨도 실행돼야 한다(단계마다 확인할 수 있게).
- 워크시트에 실리는 줄은 워크시트와 글자 하나까지 같다([02-content-rules.md](02-content-rules.md) 코드 규칙).
- 출력 문구는 아이 눈높이 한국어로 쓴다.
- 예외: 마지막 단계에서 `#`으로 숨기는 테스트용 줄은 solution에 주석 상태로 둔다(spec의 `sol_lines`). 교안과 이 한 줄만 다르다 (2차 피드백)

## README.md (교안 요약)

GitHub에서 바로 읽히는 요약이다(P11). 교안(`lesson.html`)과 같은 흐름으로 쓴다.

1. 미션 브리핑: 이야기, 완성하면 이렇게 돼요(실행 예시), 오늘의 미션
2. 워밍업: 오류 메시지 읽고 고치기
3. 단계별로 기능 쌓기: 단계마다 목표 → 도구 카드 → 기능 추가하기 코드 → 실행해서 확인할 것(성공 체크)
4. 내 것으로 바꾸기(체크리스트), 새로 만들기. 힌트는 `<details>`로 접어 둔 3단계
5. 도전 프로젝트: 바꾸기부터, 힌트 3단계
6. 오늘의 체크리스트

교안과 내용이 어긋나지 않게 한다. 교안의 코드·힌트·문구를 고치면 README도 같이 고친다. 쓰는 칸 대신 "무엇을 적는지"만 짧게 쓴다.
- 힌트 코드는 코드 블록으로, 인라인 코드는 백틱으로 쓴다. HTML 기호(`&lt;` 등)가 남으면 안 된다. 워밍업 팁, 따라가기, 친구에게 보여 주기, 오늘의 마무리, 도전 표·더 해 보기도 넣는다(생성 도구가 만든다) (2차 피드백)

## teacher_guide.md

- 110분 시간 배분 표, 핵심 설명 포인트, 자주 나오는 오류와 대처, 진도 차이 대응
- 커리큘럼 "참고"의 주의점은 해당 주차 교사 가이드에 적는다(예: round()는 끝자리가 5일 때 짝수 쪽으로 맞춰서 round(2.5)가 2가 된다).
- "미니 따라 하기 정답(빈칸)" 절은 쓰지 않는다. **"단계별 확인"**(단계마다 확인할 화면, 자세한 답은 `answer_key.md`)으로 쓴다 (2차 피드백)
- 진도 차이 대응의 느린 학생 목표는 "단계 N까지 실행 + ★ 1~2개"처럼 쓴다. 교안에 실제로 있는 활동 이름을 쓴다 (2차 피드백)
- 숫자 입력 단계가 있으면 ValueError(숫자 대신 글자를 넣었을 때) 대처를 한 줄 적는다 (2차 피드백)
- 인쇄 안내: "양면 인쇄를 권장한다" 한 줄을 넣는다 (2차 피드백)

## answer_key.md 형식

- 맨 위에 "교사용. lesson.html의 블록 순서대로 정리했다."라고 적는다.
- 제목은 블록 이름과 같게 쓴다(예: `## 🪜 단계 1 · 제목 보여 주기`). 예전 형식 주차는 `## N쪽 · 섹션 이름`
- 넣을 것:
  - 워밍업 오류 표: 줄 번호, 오류 이름(실제 메시지), 고친 방법. 오류가 나타나는 순서도 적는다.
  - 따라가기 미션 표의 값
  - 단계마다 실행하고 확인 칸의 답(입력값과 화면, 실제로 실행한 값)
  - 따라 하기 빈칸 답
  - 판정 표·예상 표·계산 문제의 답
  - 학생마다 다른 칸은 "예시"와 "확인할 점"
- 실행 결과는 **실제로 코드를 돌려서 확인한 값**만 쓴다. 확인했으면 "(실행해 확인함)"이라고 적는다.
- 교과 사실(수치, 연도 등)은 근거와 함께 적는다.
- 워밍업 표에는 **오류가 나타나는 순서**와 **실제 메시지**(Python 3.11)를 적는다. 고치면 줄 번호가 밀리는 경우도 적는다 (2차 피드백)
- 변수 이름, 화면에 나오는 값(반올림 등)은 실제 파일·실행 결과와 같게 적는다 (2차 피드백)
