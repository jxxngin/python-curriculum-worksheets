# 2주차 교사 가이드: 밸런스 게임

## 수업 목표

- if/elif/else로 분기하고, ==로 문자열을 비교한다.
- input() 값은 문자열이므로 `"1"`과 비교해야 함을 이해한다.
- strip()으로 입력 공백을 정리한다.

## 핵심 설명 포인트

- `=`(대입)와 `==`(비교)의 구분이 오늘의 핵심. 1주의 "상자에 넣기"와 대비시킨다.
- 들여쓰기는 블록 코딩에서 "만약" 블록 안에 끼워 넣은 블록과 같다. 대부분의 편집기는 `:` 뒤 Enter 시 자동 들여쓰기를 해 준다.
- 위에서부터 검사해 처음 맞는 하나만 실행된다. 코드를 한 줄씩 함께 따라가며 보여 주면 이해가 빠르다.
- 단계 4는 `title`에 기본값("엉뚱한")을 먼저 넣고 조건이 맞을 때만 바꾸는 방식이다. 같은 상자에 다시 넣으면 값이 바뀐다는 1주 내용을 다시 쓴다. 따라가기 표로 "3"을 넣으면 왜 "엉뚱한"이 남는지 확인한다.
- `input()`은 항상 문자열을 돌려준다. `pick == 1`은 오류 없이 항상 거짓 → "오류 메시지 없는 오류(논리 오류)" 개념 소개. 숫자 변환(int())은 다음 주에 배운다.
- 이번 주는 and/or를 쓰지 않는다(6주). 여러 답을 허용하려면 elif를 늘리게 한다.
- 도전: 문자열 이어 붙이기(1주)로 성향 코드를 만드는 아이디어가 핵심. 질문 3개 → 8가지 경우의 수를 빠짐없이 나열하는 것 자체가 경우의 수 학습이 된다.

## 자주 나오는 오류와 대처

| 증상 | 원인 | 대처 |
| --- | --- | --- |
| `SyntaxError: expected ':'` | 조건 끝 `:` 누락 | if/elif/else 줄 끝 확인 |
| `IndentationError: expected an indented block` | 들여쓰기 누락 | Tab 또는 스페이스 4칸 |
| `IndentationError: unindent does not match` | 들여쓰기 칸 수가 섞임 | 블록 전체 선택 후 다시 들여쓰기 |
| `SyntaxError: invalid syntax. Maybe you meant '=='` | 조건에 `=` 사용 | `==`로 수정 |
| 항상 else만 실행 | `"1"` 대신 `1`과 비교, 앞뒤 공백, 대소문자(`a`≠`A`) | 따옴표·strip() 확인. `print(snack)`을 넣어 실제 값 확인 |
| `elif`가 `if` 없이 단독 | if 블록이 중간에 끊김 | 들여쓰기 정렬 |

## 워밍업 정답

1. 9번째 줄: `if snack = "1":` → `if snack == "1":` (SyntaxError)
2. 13번째 줄: `else` → `else:` (SyntaxError)
3. 11번째 줄: `elif snack == 2:` → `elif snack == "2":` (오류 메시지 없음, 2를 입력해도 else가 실행되는 논리 오류)

## 단계별 확인

단계마다 실행 결과와 따라가기 답은 `answer_key.md`에 있다. 단계 2는 6줄이라 들여쓰기 실수가 가장 많다. `if`/`elif`/`else` 줄은 맨 앞에서 시작하고, `print` 줄만 4칸 들여 쓰는지 확인한다.

## 진도 차이 대응

- 빠른 학생: 새로 만들기("치킨"이라고 대답해도 알아듣기) → 🚀 도전(성향 테스트). 도전 더 해 보기의 소문자 처리는 받자마자 대문자로 바꾸는 방식(`if q1 == "a":` / `q1 = "A"`)으로 안내한다(upper()는 3학기).
- 느린 학생: ★ 꼭 하기 중 질문 바꾸기 + 선택지 3개 질문 1개를 최소 목표로 한다. 들여쓰기 오류가 반복되면 편집기 자동 들여쓰기에 맡기도록 한다.
- 결과 문구를 꾸미는 데 시간을 너무 쓰지 않도록 코드 먼저, 문구는 나중에.

- 인쇄: 양면 인쇄를 권장한다.
