# 9주차 교사 가이드: 설계와 보충 (기말 설계도)

## 수업 목표

- 기말 주제를 정하고 최소 완성 기준을 이해한다.
- 화면 흐름, 변수·리스트 표, 순서도로 설계도를 그린다.
- 1~8주 개념 중 부족한 부분을 작은 프로그램 바꾸기(보충 문제)로 다시 쓴다.

## 110분 시간 배분

교안: `lesson.html`. 새 개념이 없는 완충 주간이라 기본값(15/40/10/30/15분)을 설계 흐름에 맞춰 쓴다.

| 시간 | 활동 | 비고 |
| --- | --- | --- |
| 0~15분 | 미션(방탈출 예시 화면) + 워밍업: 보물 상자 고치기 | 10~11주 예시 답안을 실행해 보여 주면 좋다 |
| 15~55분 | 단계 1 주제·화면 흐름 → 단계 2 변수·리스트 표·순서도 | 학생별로 돌며 점검 |
| 55~65분 | 쉬는 시간 |  |
| 65~95분 | ⭐ 설계도 점검(★ 3개) · 친구에게 1분 설명 · 💡 보충 문제 | 설계가 늦은 학생은 설계 마무리 |
| 95~110분 | ✅ 마무리, 다음 주 예고(만들기 시작, `time.sleep()` 명령 카드) |  |

## 핵심 설명 포인트

- 최소 완성 기준은 커리큘럼 그대로다. "이보다 더 만든 것은 추가 기능"이므로 설계에서 최소 기준을 먼저 채우고, 추가 기능은 더 해 보기에 따로 적게 한다.
  - 수학 문제 방탈출: 방 3개, 방마다 무작위 문제를 맞힐 때까지 반복, 목숨 3개, 열쇠 리스트
  - 펫과 함께하는 하루: 10턴, 행동 3개(밥, 놀기, 재우기), 배고픔·기분 수치 2개, 행복도로 성공·실패 판정
  - 청소년 창업 시뮬레이션(커리큘럼의 확장, 교안에는 🚀 어려움 표시): 7일 영업, 돈·평판 수치 2개, 판매 상품 리스트, 무작위 사건 3개, 목표 금액 달성 여부 판정
- 1~8주 프로젝트를 교과 주제로 키우는 경우에도 `while`, 리스트, 조건, `random`이 모두 들어가게 한다.
- 화면 흐름은 "시작 → 되풀이되는 화면 → 끝" 3칸이 최소다. 되풀이되는 화면에 한 턴에 보일 글자를 실제로 쓰게 한다.
- 변수 표에서 "처음 값"과 "언제 바뀌나요?"를 꼭 쓰게 한다. 누적 변수의 처음 값 위치 실수(7주)를 설계에서 미리 막는다.
- 순서도는 블록 코딩 경험을 살려 "반복 블록 안에 무엇이 들어가나"로 설명한다. 네모(하는 일)와 마름모(조건)만 쓴다.
- `len()`, `for`, 함수(`def`)는 아직 배우지 않았다. 설계에서 필요해 보이면 `while` + 횟수 상자, 리스트 `in`으로 대신하게 한다. 개념 체크 칸에도 1~8주 개념만 넣었다.
- 보충 문제는 빈칸 없이 그대로 실행되는 작은 프로그램이다. 실행하면 번호를 묻고 그 문제만 실행되므로, 안 푼 문제를 주석 처리할 필요가 없다.

## 설계도 예시 (펫과 함께하는 하루, 교사 참고용)

- 화면 흐름: 펫 이름 입력·인사 → [n턴] 배고픔·기분 표시, 행동 1~3 선택, 무작위 반응 → 10턴 끝, 행복도와 성공/실패
- 변수: `turn`(턴, 1, 매 턴 +1), `hunger`(배고픔, 5, 밥 -3/매 턴 +1), `mood`(기분, 5, 놀기 +3/재우기 +1), `happy`(행복도, 끝에 계산)
- 리스트: `toys = ["공"]`(놀 때 `random.choice`, 사건으로 append), `diary`(매 턴 행동 기록 append)
- 순서도: 시작 → `turn <= 10`? → 표시 → 입력 → 행동 나누기 → 수치 범위 맞추기 → `turn + 1` → (위로) → 아니요 → 행복도 ≥ 기준? → 성공/실패

## 자주 나오는 문제와 대처

| 증상 | 원인 | 대처 |
| --- | --- | --- |
| 설계도가 너무 큼(맵, 상점, 레벨…) | 최소 기준과 추가 기능 구분 없음 | 최소 기준을 먼저, 나머지는 더 해 보기 칸에 |
| 화면 흐름에 반복이 안 보임 | 시작·끝만 그림 | "몇 번 되풀이되는 화면은 어디?" 질문 |
| 변수 표가 비어 있음 | 무엇이 바뀌는지 모름 | 화면에 숫자로 보이는 것 = 변수 |
| 보충 문제에서 IndentationError | 문제 안의 줄을 4칸보다 적게 씀 | 고른 문제 안(`if pick == "N":` 아래)은 모두 4칸 이상 |
| 보충 문제 4·5번에서 ValueError | 숫자 대신 글자 입력 | 질문의 "(숫자만)"을 가리키고 다시 실행 |

## 워밍업 정답

순서: 13번(SyntaxError) → 7번(IndexError) → 16번(메시지 없음).

1. 13번째 줄: `if pick = "금 열쇠":` → `==` (SyntaxError, 실행 전에 나온다)
2. 7번째 줄: `keys[3]` → `keys[2]` (IndexError, 3칸이라 번호는 0~2)
3. 16번째 줄: `{tries - 3}` → `{3 - tries}` (메시지 없음. 틀리면 `남은 기회: -2`. 힌트 블록의 `워밍업` 카드에 고치는 모양이 있다)

## 진도 차이 대응

- 빠른 학생: 설계도를 자세히(추가 기능, `time.sleep()` 연출 자리) → 보충 문제.
- 느린 학생: 단계 1(주제·화면 흐름) + ★ 1개(최소 기준을 설계도에 넣기)를 최소 목표로. 변수 표와 순서도는 10주 시작 전에 교사와 함께 채운다.
- 개념이 약한 학생: 선생님이 보충 문제 번호를 골라 준다(예: 7주가 약하면 5번).
- 인쇄: 양면 인쇄를 권장한다.
- 다음 주는 만들기 시작. 설계도를 꼭 가져오게 한다.
