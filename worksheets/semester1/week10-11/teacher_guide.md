# 10~11주차 교사 가이드: 기말 프로젝트

## 수업 목표

- 9주 설계도대로 고른 주제의 최소 완성 기준을 모두 채운 프로그램을 만든다.
- `time.sleep()`(명령 카드)으로 기다리는 연출을 넣는다.
- 친구 테스트로 고칠 점을 찾고, 11주 마지막에 발표한다.

## 2주 시간 배분

교안: `lesson.html` 하나를 두 주 동안 쓴다. 10주는 미션·10주 워밍업·단계 1~2, 11주는 11주 워밍업·단계 3~4·완성 기준·발표다.

| 시간 | 10주 | 11주 |
| --- | --- | --- |
| 0~15분 | 미션(예시 화면) + 10주 워밍업: 탐험가의 가방 | 11주 워밍업: 목숨 계산기 |
| 15~55분 | 단계 1 명령 카드·시작 파일 실행 → 단계 2 최소 기준 만들기 | 남은 최소 기준 마무리 → 단계 3 친구 테스트 |
| 55~65분 | 쉬는 시간 | 쉬는 시간 |
| 65~95분 | 단계 2 계속 (목표: 기준 절반 이상) | 💡 추가 기능 · 단계 4 발표 준비 → 발표(1인 3분) |
| 95~110분 | 오늘 만든 기준 체크, 다음 주 할 일 정하기 | ⭐ 기말 완성 기준 확인, ✅ 마무리, 1학기 돌아보기 |

## 핵심 설명 포인트

- 주제는 9주에 고른 것으로 한다. 세 주제 중 택1이고, 청소년 창업 시뮬레이션(커리큘럼의 확장)은 교안에 🚀 어려움으로 표시했다. 1~8주 프로젝트를 교과 주제로 키운 경우는 `while`, 리스트, 조건, `random`을 모두 쓰면 된다.
- 최소 완성 기준(커리큘럼 그대로)은 ⭐ 블록의 주제별 체크 목록에 있다. ★ 3개는 "기준 모두 · 친구 테스트 · 발표"다. 기준보다 더 만든 것은 추가 기능이고 평가에 넣지 않는다.
- 시작 파일은 셋 다 그대로 실행되고, 맨 위 주석에 그 주제의 기준 체크리스트와 `# TODO`가 있다. "주석의 체크리스트 순서대로, 하나 만들면 실행"을 계속 말한다.
- `time.sleep()`은 명령 카드다. 0.5~2초가 알맞고, 반복 안에 넣으면 턴마다 기다린다는 점을 짚는다.
- 방탈출은 "방 반복 안에 문제 반복"(이중 반복)이다. 바깥 조건에 `and lives > 0`이 없으면 목숨이 0이어도 다음 방으로 간다.
- 펫은 수치 범위(0~10)를 지키는 `if` 두 줄이 자주 빠진다. 시작 파일을 밥 주기만으로 돌리면 배고픔이 음수가 되는 것을 보여 주면 필요성을 바로 안다.
- 창업은 `continue`로 메뉴에 없는 상품을 다시 받으면 그날이 지나가지 않는다는 점(7주와 같음)을 확인한다.
- 친구 테스트는 성공·실패 두 경우를 모두 끝까지 해 보는 것이 기준이다. 끝까지 오래 걸리면 목숨·턴 수를 잠깐 줄여 시험하고 다시 돌려 놓게 한다.
- 인쇄 분량이 16쪽이다. 두 주에 나눠 쓰므로 10주에 앞쪽(단계 2까지), 11주에 뒤쪽을 나눠 주어도 된다.

## 자주 나오는 오류와 대처

| 증상 | 원인 | 대처 |
| --- | --- | --- |
| `AttributeError: module 'time' has no attribute …` | `sleep` 철자 | `time.sleep(1)` |
| `NameError: name 'time' is not defined` | `import time` 없음 | 맨 위에 `import time` |
| 목숨·턴이 0이 돼도 안 끝남 | 반복 조건에 목숨·턴이 없음, 줄이는 줄이 없음 | `while ... and lives > 0:`, `lives = lives - 1` |
| 수치가 10을 넘거나 음수 | 범위를 지키는 `if`가 없음 | `if mood > 10: mood = 10` 등 |
| `ValueError` | 숫자 질문에 글자를 넣음 | 질문에 "(숫자만)"을 붙이고 다시 실행 |
| 마지막 판정이 반복 안에서 매번 나옴 | 판정 줄을 4칸 들여 씀 | 반복이 끝난 뒤(0칸)로 |

## 워밍업 정답

10주 순서: 14번(SyntaxError) → 9번(AttributeError) → 18번(NameError).

1. 14번째 줄: `if want in items` → `if want in items:` (SyntaxError, 실행 전에 나온다)
2. 9번째 줄: `time.slep(2)` → `time.sleep(2)` (AttributeError, 힌트 블록의 `10주 워밍업` 카드에 고치는 모양이 있다)
3. 18번째 줄: `tries`가 없다 → 반복 전 11번 빈 줄에 `tries = 0` (NameError, 없는 물건을 넣어야 나온다). 빈 줄에 넣으면 줄 번호가 밀리지 않는다.

11주 순서: 11번(IndentationError) → 15번(TypeError) → 메시지 없음.

1. 11번째 줄: `keys.append("1번 열쇠")` 앞에 4칸 더(8칸) (IndentationError, 실행 전에 나온다)
2. 15번째 줄: `"땡! 남은 목숨: " + lives` → `f"땡! 남은 목숨: {lives}"` (TypeError, 틀린 답을 넣으면 나온다)
3. 메시지 없음: 틀려도 `남은 목숨: 3`이 계속 나온다 → 14번 빈 줄에 `    lives = lives - 1` (힌트 블록의 `11주 워밍업` 카드)

## 단계별 확인

- 단계 1: 시작 파일이 끝까지 실행되고 `time.sleep()` 자리를 하나 더 만들었다 / 단계 2: 기준을 만들 때마다 실행해 체크 / 단계 3: 성공·실패 두 경우를 친구가 끝까지 / 단계 4: 발표 다섯 칸. 자세한 내용은 `answer_key.md`.

## 진도 차이 대응

- 빠른 학생: 💡 추가 기능(주제별 아이디어, 무작위 사건 힌트) → 틀린 입력에도 멈추지 않게 다듬기.
- 느린 학생: 11주 첫 시간까지 최소 기준을 마치는 것이 목표다. 주제별 힌트 카드(방탈출·펫·창업 뱃지)의 ●●● 거의 코드를 시작 파일에 넣어 실행해 보게 하고, 그다음 내 것으로 고치게 한다.
- 기준을 끝내지 못한 학생도 발표는 한다. 만든 데까지 시연하고, 남은 기준을 "다음에 더할 기능"으로 말하게 한다.
