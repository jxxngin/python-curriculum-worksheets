# 10~11주차 교사 가이드: 기말 프로젝트

## 수업 목표

- 9주 설계도를 바탕으로 기말 프로젝트를 최소 완성 기준까지 구현한다.
- time.sleep()으로 출력 연출을 한다(명령 카드).
- 1~9주 개념(조건, 논리 연산, while/break/continue, 누적 변수, 리스트, random)을 통합해 쓴다.
- 11주에 발표하고 서로 평가한다.

## 기말 최소 완성 기준 (커리큘럼 그대로)

- 수학 문제 방탈출: 방 3개, 방마다 무작위 문제를 맞힐 때까지 반복, 목숨 3개, 열쇠 리스트
- 펫과 함께하는 하루: 10턴, 행동 3개(밥, 놀기, 재우기), 배고픔·기분 수치 2개, 행복도로 성공·실패 판정
- 청소년 창업 시뮬레이션: 7일 영업, 돈·평판 수치 2개, 판매 상품 리스트, 무작위 사건 3개, 목표 금액 달성 여부 판정

이보다 더 만든 것은 추가 기능으로 본다. 1~9주 프로젝트를 교과 주제로 키운 학생은 while, 리스트, 조건, random 사용을 최소 기준으로 삼는다.

## 핵심 설명 포인트

- time.sleep(초)은 import time이 필요하다. 4주 import random과 같은 방식. 소수도 된다. 디버거로 실행하면 sleep 줄에서 잠깐 멈춘다.
- 과한 sleep은 테스트를 느리게 만든다. 개발 중에는 짧게, 발표 때 늘리게 한다.
- 방탈출의 핵심은 이중 while(방 반복 안에 문제 반복)과 두 반복을 모두 끝내는 조건(lives > 0). 바깥 조건에 `and lives > 0`이 없으면 목숨이 0이어도 다음 방으로 넘어간다.
- 펫은 수치 범위 제한(0~10)을 if로 처리하게 한다. 잘못된 입력은 continue로 턴을 소모하지 않게 하면 좋다.
- 창업은 밸런스 조정이 곧 수학 활동이다. 손님 수 범위, 가격 반응, 목표 금액을 바꿔 가며 "7일 평균 수입"을 계산해 보게 한다. 예시 답안은 목표 100000원으로 전략에 따라 성공·실패가 갈린다.
- 시작 코드의 `# TODO`를 체크리스트처럼 쓰게 한다. 한 기능을 넣을 때마다 실행해서 확인하는 습관(작게 만들고 자주 실행).
- 아직 배우지 않은 len(), for, def, 리스트 remove() 등은 쓰지 않는다. 학생이 원하면 "2학기에 배우면 더 짧아진다"고 예고만 한다.
- `int(input())`에 글자를 넣으면 ValueError로 멈춘다. 오류 처리(try/except)는 3학기 내용이므로 "숫자를 입력하세요" 안내 문구로 대신한다.

## 자주 나오는 오류와 대처

| 증상 | 원인 | 대처 |
| --- | --- | --- |
| `AttributeError: ... 'slep'` | 철자 | time.sleep |
| `NameError: name 'time' is not defined` | import time 누락 | 맨 위에 import |
| 목숨 0인데 다음 방으로 감 | 바깥 while 조건에 lives 검사 없음 | `while room <= 3 and lives > 0:` |
| 같은 문제만 계속 나옴 | random 줄이 반복 밖 | 문제 만들기를 안쪽 while 안으로 |
| 수치가 음수/10 초과 | 범위 제한 없음 | 턴 끝에 if로 자르기 |
| 열쇠 리스트가 매 방마다 비워짐 | `keys = []`가 반복 안 | 반복 전으로 이동 |
| 날짜가 안 넘어감/무한 반복 | continue가 day 증가 전에 와서 계속 같은 날 | 의도한 것인지 확인, 입력 안내 |
| 프로그램이 너무 느림 | sleep 과다 | 개발 중에는 0.2초 |

## 워밍업 정답

1. 14번째 줄: `if want in items` → 끝에 `:` (SyntaxError)
2. 9번째 줄: `time.slep(2)` → `time.sleep(2)` (AttributeError)
3. 반복 전에 `tries = 0` 추가 (18번째 줄 NameError, 없는 물건을 입력했을 때만 나온다). 예: 11번째 줄에 `tries = 0`

| 항목 | 기준 |

## 진도 차이 대응

- 느린 학생: 펫 주제 권장. 시작 코드에 행동 2개 추가 → 행복도 판정 순서로 최소 기준만. 예시 답안의 일부(수치 범위 제한)를 보고 따라 써도 된다.
- 보통: 최소 기준 + 추가 기능 1개(등급, 무작위 사건, 일기 리스트).
- 빠른 학생·중고등: 창업 시뮬레이션. 상품별 손님 반응 차이, 평판에 따른 손님 수, 밸런스 표 작성. 방탈출 선택 시 방마다 다른 연산 + 난이도 선택.
- 발표일은 공통으로 고정한다. 미완성이어도 된 데까지 시연하고, 남은 계획을 발표하게 한다.
