# 8주차 교안 정답지: 탐정의 용의자 명단

교사용. `lesson.html`의 블록 순서대로 정리했다. 실행 결과는 `mini_solution.py`를 제작 환경(Python 3.8)에서 실제로 실행해 확인했고, 이 코드들은 3.11에서도 결과가 같다. 오류 메시지는 수업 기준인 Python 3.11 문구로 적었다.

## 🎯 미션

"완성하면 이렇게 돼요"는 옆 반 친구 / 택배 기사님 / 옆 반 친구를 넣고 실행한 화면이다.

## 🔧 워밍업 (고장 난 간식 뽑기 고치기)

| 나타나는 순서 | 줄 | 오류 이름 (실제 메시지) | 고친 방법 |
| --- | --- | --- | --- |
| 1 | 8 | 메시지 없음 (첫 번째 후보가 `과자`로 나온다) | `snacks[0]` (칸 번호는 0부터) |
| 2 | 10 | AttributeError (`'list' object has no attribute 'add'`) | `snacks.append("아이스크림")` (워밍업 힌트 카드) |
| 3 | 12 | IndexError (`list index out of range`) | `snacks[3]` (4칸이라 번호는 0~3) |

- 실행하면 8번 줄이 `첫 번째 후보: 과자`를 오류 없이 보여 준다(메시지 없는 오류). 이어서 10번에서 AttributeError가 난다. append로 고치면 11번이 4칸 명단을 보여 주고 12번에서 IndexError가 난다. 다 고치면 `마지막 후보: 아이스크림`, `🍬 오늘의 간식: …`(넷 중 하나를 새로 뽑는다)이 나온다.

## 🪜 단계 1 · 용의자 명단 만들기

- 실행하고 확인: `가장 먼저 의심받는 사람: 옆집 고양이`

## 🪜 단계 2 · 수상한 사람 더하기

- 실행하고 확인: `새 명단: ['옆집 고양이', '배고픈 동생', '택배 기사님', '(적은 이름)']`

## 🪜 단계 3 · 범인 몰래 뽑기

- 실행하고 확인: `범인이 정해졌어요. 기회는 3번!` 범인은 4명 중 하나를 새로 뽑는다. 같은 사람이 다시 뽑혀도 정상이다.

## 🪜 단계 4 · 명단에 있는 사람만 조사하기

- 실행하고 확인: (수상한 사람은 삼촌) 피자 → `명단에 없는 사람이에요.` / 배고픈 동생·옆집 고양이 → 아무 말 없이 다시 묻는다 / 택배 기사님(세 번째) → 프로그램이 끝난다

## 🪜 단계 5 · 범인 판정하기

- 실행하고 확인: 마지막 줄: `사건 기록: 범인은 (뽑힌 사람)`

**따라가기** (범인이 배고픈 동생이고, 새 사람으로 삼촌을 적은 뒤 택배 기사님 / 피자 / 배고픈 동생을 넣으면?, 실행해 확인함)

| 넣은 이름 | tries | 나온 말 |
| --- | --- | --- |
| 택배 기사님 | 1 | `택배 기사님: 알리바이가 있어요.` |
| 피자 | 1 (그대로) | `명단에 없는 사람이에요.` |
| 배고픈 동생 | 2 | `정답! 범인을 찾았어요.` → `break` → `사건 기록: 범인은 배고픈 동생` |

## ⭐ 내 것으로 바꾸기

- 예시는 `mini_solution.py` 맨 아래 주석(용의자 여러 명, 단서 두 자리). 용의자 추가 반복은 7주의 `while True` + `break` + `continue` 모양을 다시 쓴다. 단서는 틀릴 때마다 새로 뽑으므로 같은 단서가 다시 나와도 정상이다.
- 완성 기준은 ★ 3개다. 더 해 보기는 평가에 넣지 않는다.

## 🚀 도전 프로젝트 (이상형 월드컵)

- 시작 파일에서 1만 계속 넣으면 4강은 `[0]`, `[2]`, `[4]`, `[6]` 칸 후보다(`떡볶이, 카레, 치킨, 스파게티`, 실행해 확인함). 거의 코드 힌트로 바꾸면 1만 넣을 때 우승은 `[0]` 칸 후보다. 예시 답안 `extension_solution.py`는 우승까지 반복, 라운드 제목, 잘못된 입력 `continue`, `random.shuffle()` 대진, 탈락자 명단, "?" 입력 시 `random.choice()`로 고르기를 담았다.
