# 6주차 교사 가이드: 놀이공원 입장 판정기

## 수업 목표

- and/or/not으로 조건 두 개를 묶어 판정한다.
- True/False(참·거짓)를 이해하고 깃발 변수로 여러 조건을 한 번에 확인한다.
- 중첩 if로 두 번 나눠 판정한다.
- (도전) 비교 결과를 상자에 담아 규칙 기반 판단을 만든다.

## 핵심 설명 포인트

- `True`/`False`는 첫 글자 대문자, 따옴표 없음. `"True"`(글자)와 다르다. 단계 4에서 `print`로 True/False가 그대로 보이게 했다.
- `x == "a" or "b"`는 늘 참이 된다(비어 있지 않은 글자는 참으로 본다). "or 양쪽에는 비교를 각각 다 쓴다"로 지도하고 원리는 깊이 설명하지 않는다.
- 깃발 변수와 and 비교: and는 한 줄로 판정하지만, 깃발은 조건을 하나씩 확인해 이유별 메시지를 붙이기 쉽다. 바꾸기의 `if not can_ride:`가 깃발을 다시 쓰는 예다.
- 중첩 if는 "첫 관문을 통과한 사람만 두 번째 관문". 들여쓰기 칸 수가 곧 구조다. 따라가기에서 자유이용권이 없으면 나이를 보지 않는다는 것을 확인한다.
- 경계값 테스트(119/120, 9/10)를 습관으로 만든다. `>`와 `>=` 실수를 스스로 찾게 한다.
- 도전: 판단 순서(위험한 것 먼저)가 곧 AI의 "우선순위 규칙"이다. 규칙 기반 AI라는 말을 소개하고, 실제 자율주행은 데이터로 학습한다는 점은 맛보기로만 말한다. 보행자 보호 우선 같은 판단도 짧게 이야기할 수 있다.
- 도전 예시 답안의 무작위 모드는 `person = person_n == 1`처럼 비교 결과를 True/False로 담는다. random.choice()는 8주 개념이라 쓰지 않는다.

## 자주 나오는 오류와 대처

| 증상 | 원인 | 대처 |
| --- | --- | --- |
| `NameError: name 'true' is not defined` | 소문자 true/false | 대문자 True/False |
| 늘 참 | `a == "x" or "y"` | `a == "x" or a == "y"` |
| `IndentationError` | 중첩 if 들여쓰기 | 안쪽 if·else는 4칸, 그 안의 print는 8칸 |
| else가 엉뚱한 if에 붙음 | else 들여쓰기 위치 | 짝이 되는 if와 같은 칸에 |
| 깃발이 늘 True | 깃발 세우기를 조건 아래에 씀 | `can_ride = True`는 검사보다 위에 |
| 보호자와 왔는데 못 탄다고 나옴 | `with_parent == "네 "`처럼 공백 | `.strip()` 확인 |

## 워밍업 정답

순서: 19번(IndentationError) → 8번(NameError) → 10번(메시지 없음).

1. 19번째 줄: `print("😎 …")` 앞에 4칸 들여쓰기 (IndentationError, 실행 전에 나온다)
2. 8번째 줄: `false` → `False` (NameError, 질문 두 개에 대답한 뒤 나온다)
3. 10번째 줄: `if rain == "네" or "흐림":` → `if rain == "네":` (메시지 없음. 비도 안 오고 맑아도 우산을 챙기라고 한다. 힌트 블록의 `워밍업` 카드에 고치는 모양이 있다)

## 진도 차이 대응

- 빠른 학생: 새로 만들기(오늘의 VIP, 키 재기 기계) → 도전 프로젝트.
- 느린 학생: 단계 5까지 실행 + ★ 1~2개(안내 문구 바꾸기, 놀이기구 1개 추가)를 최소 목표로.
- 숫자 대신 글자를 넣으면 ValueError로 멈춘다. 질문 문구의 "(숫자만)"을 가리키고 다시 실행하게 한다.
- 단계 2·3·4는 표의 값을 넣으려면 처음부터 다시 실행해야 한다. 질문 순서(이름 → 나이 → 키 → 자유이용권 → 보호자)를 미리 알려 주면 빨라진다.
- 인쇄: 양면 인쇄를 권장한다(16쪽).
- 다음 주는 while. "기회를 여러 번 주고 싶다"는 요구가 나오면 예고로 쓴다.
