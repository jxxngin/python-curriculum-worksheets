# 6주차 교사 가이드: 놀이공원 입장 판정기

## 수업 목표

- and/or/not으로 복합 조건을 만든다.
- 중첩 if로 단계적 판정을 한다.
- True/False(bool)를 이해하고 깃발 변수로 상태를 기억한다.

## 110분 시간 배분

| 시간 | 활동 | 비고 |
| --- | --- | --- |
| 0~10분 | 중간 프로젝트 피드백 한마디, 워밍업 | |
| 10~20분 | 워밍업 풀이 + 디버거로 깃발 변화 관찰 | `or "흐림"` 함정 설명 |
| 20~45분 | 개념 카드 1~4 | and/or는 진리표 대신 놀이기구 예로 |
| 45~55분 | 쉬는 시간 | |
| 55~70분 | 미니 1단계 따라 하기 | 여러 입력으로 테스트하게 |
| 70~98분 | 미니 2단계 / 중고등 확장 바꾸기 | |
| 98~106분 | 서로 판정기 테스트(경계값 넣어 보기) | 키 120, 나이 10처럼 경계값 |
| 106~110분 | 체크리스트, 다음 주 예고(while) | |

## 핵심 설명 포인트

- `True`/`False`는 첫 글자 대문자, 따옴표 없음. `"True"`(문자열)와 다르다.
- `x == "a" or "b"`는 항상 참이 된다(비어 있지 않은 문자열은 참으로 취급). "or 양쪽은 완전한 문장"으로 지도한다. 원리는 깊이 설명하지 않는다.
- 깃발 변수 vs and: and는 한 줄로 판정하지만 "왜 안 되는지" 이유를 따로 알려 주기 어렵다. 깃발은 조건마다 이유 메시지를 줄 수 있다. 두 방법을 비교시키는 것이 핵심.
- 중첩 if는 "첫 관문 통과자만 두 번째 관문". 들여쓰기 칸 수가 곧 구조라는 것을 디버거로 확인.
- 경계값 테스트(119/120, 9/10)를 습관화한다. `>`와 `>=` 실수를 스스로 발견하게 한다.
- 확장: 판단 순서(위험한 것 먼저)가 곧 AI의 "우선순위 규칙"이다. 규칙 기반 AI라는 말을 소개하고, 실제 자율주행은 데이터로 학습한다는 점은 맛보기로 언급한다. 보행자 보호 우선 같은 윤리적 판단도 짧게 토론할 수 있다.
- 확장 예시의 무작위 모드는 `person = person_n == 1`처럼 비교 결과를 bool로 저장하는 방식을 쓴다. random.choice()는 8주 개념이므로 쓰지 않는다.

## 자주 나오는 오류와 대처

| 증상 | 원인 | 대처 |
| --- | --- | --- |
| `NameError: name 'true' is not defined` | 소문자 true/false | 대문자 True/False |
| 항상 참 | `a == "x" or "y"` | `a == "x" or a == "y"` |
| `IndentationError` | 중첩 if 들여쓰기 | 안쪽 블록 8칸 확인 |
| else가 엉뚱한 if에 붙음 | else 들여쓰기 위치 | 짝이 되는 if와 같은 칸에 |
| 깃발이 항상 True | 깃발 초기화를 조건 뒤에 씀 | 깃발 세우기는 검사 전에 |
| `if can_ride == "True":` | 문자열과 비교 | `if can_ride:` |

## 워밍업 정답

1. 8번째 줄: `false` → `False` (NameError)
2. 19번째 줄: `else:` 아래 `print` 들여쓰기 (IndentationError, 가장 먼저 보고됨)
3. 10번째 줄: `if rain == "네" or "흐림":` → `if rain == "네":` (메시지 없음, 항상 참이 되는 논리 오류. 흐림은 아래 cloud 검사가 담당)

## 미니 따라 하기 정답

빈칸 1 `and`, 빈칸 2 `True`, 빈칸 3 `False`, 빈칸 4 `if`
(빈칸 1·4는 키워드 자리라 빈칸 상태로는 SyntaxError가 나는 것이 정상이다.)

## 진도 차이 대응

- 빠른 학생: 미니 3단계(기구 수 세기, VIP) → 확장 새로 만들기(무작위 테스트 모드).
- 느린 학생: 따라 하기 + 새 기구 1개(and 사용) + 깃발 기구 1개를 최소 목표로. 중첩 if는 따라 하기 코드로 경험한 것으로 충분.
- 중고등: 확장 바꾸기가 완성 기준. 판단 규칙을 먼저 표로 적게 한 뒤 코딩하면 오류가 줄어든다.
